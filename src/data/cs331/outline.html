Module 1Understand the world before choosing the agent.

An agent observes its environment and takes actions. A robot’s observations come through sensors; a software agent might observe files, messages, or test results. An observation is called a percept.

A rational agent chooses an action expected to produce the best outcome given its information. It can still lose or make an unsuccessful move: good decisions don’t guarantee good luck.

The introductory PEAS framework describes the job: Performance measure, Environment, Actuators, Sensors—what counts as success, where the agent operates, how it acts, and what it can observe. That’s useful orientation; the first two Module 1 explorations are excluded from the exam.

The examinable material starts with what kind of environment the agent faces:

Task environment dimensions
Dimension The actual question
Fully / partially observableCan I see everything relevant to my decision? Poker hides opponents’ cards.
Single / multiple agentsAre other decision-makers affecting the outcome? They may cooperate or compete.
Deterministic / nondeterministicDoes the same state plus the same action always produce the same result?
Episodic / sequentialIs each decision independent, or does it change later decisions? Independent image classification is episodic; a crossword is sequential.
Static / dynamicCan the world change while I’m thinking? In the course’s “semi-static” case, the world stays fixed while the performance measure changes, as with a running chess clock.
Discrete / continuousAm I choosing among distinct moves, or working with continuously varying quantities?
Known / unknownDo I understand the rules and effects of actions?

Known and observable are separate. You can know every rule of poker while being unable to see someone’s cards.

The next question is what machinery the agent needs:

  • Simple reflex: follows a rule based on the current observation. “If dirty, clean.”
  • Model-based: maintains an internal picture of the world. It can remember information that isn’t currently visible. Its transition model describes how the world changes; its sensor model describes how world states produce observations.
  • Goal-based: considers future actions to reach a desired state. “How do I get both rooms clean?”
  • Utility-based: ranks outcomes so it can make tradeoffs. “How much cleanliness is worth this much time and energy?”
  • Learning: improves through experience. This can improve any of those agent types. The performance element acts, the learning element improves it, the critic supplies feedback, and the problem generator suggests informative exploration.

Finally, the course distinguishes state representations:

  • Atomic: a state is one indivisible label.
  • Factored: a state contains variables and values.
  • Structured: a state contains objects and relationships.

That distinction comes back in Module 5: exposing variables lets an algorithm reason directly about constraints.

What understanding looks like: you can classify a scenario and explain which agent design fits it. Module 1 scope

Module 2Find a sequence of actions that reaches a goal.

Suppose Pacman needs to reach some food. Before selecting an algorithm, define the problem:

  • State: the information needed to decide what can happen next. For navigation, position might suffice; collecting all food also requires tracking which food remains.
  • Initial state: where we start.
  • Actions and transition model: legal moves and their results.
  • Goal test: how we recognize success.
  • Action costs: how we compare different routes.

A state is a situation. A search node represents reaching a situation along a particular path, including its parent and accumulated cost. Different paths can reach the same state.

This explains a surprising fact: a finite world can produce an infinite search tree. Two rooms are a finite state space, but “left, right, left, right…” can continue forever.

Search algorithms maintain a frontier: discovered possibilities waiting to be explored. Expanding a node means generating its successors. Much of this module reduces to choosing which frontier node to expand next.

Search algorithms at a glance
Algorithm What it explores next Main consequence
Breadth-first search—BFSShallowest nodes first; a queueFinds a solution with the fewest actions. That also means lowest cost when actions cost the same. Can use enormous memory.
Depth-first search—DFSFollows the current branch deeply; a stackUses relatively little frontier memory, but can pursue a bad branch indefinitely and doesn’t guarantee lowest cost.
Uniform-cost search—UCSLowest cost accumulated so farFinds the cheapest route under the standard positive-cost assumptions.
Greedy best-firstAppears closest to the goalCan be fast, but an attractive-looking route can be expensive overall.
A*Lowest cost so far plus estimated remaining costCombines what you’ve already spent with what you expect remains. Can preserve optimality with an appropriate heuristic and correct search handling.

Two related methods:

  • Depth-limited search: DFS with a maximum depth. It avoids descending forever, but can miss a deeper solution.
  • Iterative deepening: repeatedly runs depth-limited search with increasing limits. It gets BFS’s shallowest-solution property with DFS-like memory, at the cost of repeating some work.

You compare algorithms using four questions:

  • Complete? Will it find a solution if one exists?
  • Optimal? Will it find the least-cost solution?
  • Time? How much work does it perform?
  • Space? How much must it remember?

Completeness depends on assumptions: finite branching, action costs, cycles, and duplicate handling matter. BFS, iterative deepening, UCS, and A* have completeness guarantees under their usual assumptions; unrestricted DFS and greedy search can get stuck.

The central A* vocabulary is small:

g(n) = cost so far. h(n) = estimated cost remaining. f(n) = g(n) + h(n).

A heuristic is that estimate. An admissible heuristic never overestimates the cheapest remaining cost.

  • Straight-line distance is a lower bound on a route’s geometric length.
  • Manhattan distance counts horizontal plus vertical travel. It can overestimate when diagonal shortcuts are allowed.
  • Zero is admissible for nonnegative costs, but gives no guidance. With h = 0, A* behaves like UCS.

Another recurring skill is counting possibilities: 81 independent squares with two colors each give 2^81 states. Restrictions defining the goal don’t remove all the non-goal states from the world.

What understanding looks like: you can trace the frontier, choose an algorithm for a requirement, and explain why a heuristic is safe. You don’t need to memorize complexity formulas. Module 2 scope

Module 3Handle huge spaces, unpredictable actions, and missing information.

This module contains three related complications.

First: sometimes only the final arrangement matters.

Imagine choosing locations for three fire stations to minimize the worst response time. You care about the final locations; the sequence of hypothetical layouts the algorithm considered has little value.

Local search keeps a current candidate and changes it, usually without retaining the full search history.

  • Hill climbing: repeatedly chooses an improving neighbor. For minimization, the same idea moves downhill.
  • Local optimum: better than nearby alternatives, but worse than something farther away.
  • Plateau: neighboring candidates have equal value.
  • Ridge: the landscape makes useful progress difficult with the available moves.

Suppose a minimizing algorithm follows:

10 → 8 → 7 → 4 → 2, with the remaining landscape 3 → 3 → 3 → 0.

It stops at 2. Reaching 0 requires temporarily accepting a worse value. Giving ordinary hill climbing more time doesn’t change its rule.

The alternatives address that limitation:

  • Random restarts: try again from other starting points.
  • Sideways moves: permit some equal-valued moves to cross plateaus.
  • Stochastic hill climbing: randomly choose among improving moves.
  • Simulated annealing: sometimes accepts worse moves. As its “temperature” falls, it becomes less willing to do so.
  • Local beam search: maintains k candidates and chooses the best k from their combined successors. It uses more memory; with k = 1, the course treats it as hill climbing.

Second: an action can have multiple possible results.

A fixed sequence may be inadequate when you can’t control which result occurs. You need a conditional plan: “Do this; if outcome A occurs, continue this way; if B occurs, continue another way.”

AND–OR search represents this:

  • OR: the agent chooses one action.
  • AND: the plan must handle every possible outcome of that action.
  • Every leaf in a finite, completed solution tree must reach a goal.

The word AND expresses an obligation: planning for only the lucky outcome is insufficient. Some environments also require plans with loops, such as retrying until a useful outcome occurs.

Third: you might not know the current state.

A belief state is the set of physical states still possible given your information. Here, “belief” means a set of possibilities; it needn’t mean a probability distribution.

Acting predicts where each possibility could lead. Observing removes possibilities incompatible with what you see.

A sensorless vacuum can still clean two rooms using:

Left → Suck → Right → Suck.

Left puts it in the left room regardless of its starting location; the remaining actions clean both rooms. With observations, a plan can choose different continuations based on what it senses.

The distinction to keep: uncertainty about what an action will do differs from uncertainty about where you currently are. A perfectly deterministic world can still be partially observable. Module 3 scope

Module 4Choose well when someone else is trying to beat you.

Ordinary route planning doesn’t involve an opponent deliberately selecting your worst continuation. Games do.

The main model is a deterministic, two-player, turn-taking, perfect-information, zero-sum game: both players see the position, and their interests oppose each other.

A game specifies the position, whose turn it is, legal moves, resulting positions, when play ends, and utility—a numerical payoff.

In minimax, utilities are measured from one player’s perspective:

  • MAX wants a larger number.
  • MIN wants a smaller number.
  • At MAX nodes, take the largest child value.
  • At MIN nodes, take the smallest.

Work from the leaves upward.

Suppose your first move lets the opponent choose between 12 and 6. Its minimax value is 6. Your second move lets them choose between 4 and 7, so its value is 4. You choose the first move because 6 is the better result you can secure against optimal opposition.

Alpha-beta pruning saves work once a branch cannot change that decision.

If you already have an option worth 6, and another branch lets your opponent force 4, you can stop examining that branch. Even more attractive leaves elsewhere in it won’t remove the opponent’s option to choose 4.

  • Alpha tracks the best bound already available to MAX.
  • Beta tracks the best bound already available to MIN.
  • A cutoff occurs when the bounds meet or cross: alpha ≥ beta.

Ordering changes how much gets pruned; it doesn’t change the minimax answer.

Large games also require stopping before terminal states and using a heuristic evaluation function to estimate a position’s value. That introduces estimation error. Alpha-beta itself preserves the result of searching the same tree with the same evaluations.

The lessons also introduce multiplayer extensions, where each player has a payoff; the central practice here is applying minimax and alpha-beta to small trees.

What understanding looks like: you can work backward through a tree and identify exactly which remaining branches can be skipped. Module 4 scope

Module 5Find choices that all fit together.

Think of scheduling client work: each job needs a slot, certain jobs require particular people, and nobody can occupy two places at once.

A constraint satisfaction problem—CSP— contains:

  • Variables: the choices to make.
  • Domains: the values each choice may take.
  • Constraints: the combinations allowed.

A solution is a complete, consistent assignment: every variable has a value and every constraint holds.

Constraints can involve one variable (unary), two (binary), or more. A global all-different constraint requires its participating variables to have different values.

There are two main ways to make progress.

Inference removes choices that cannot work.

To revise the directed arc (X, Y), inspect each value of X. Keep it only if at least one value of Y supports it.

Example: X = {1, 2, 3}, Y = {2}, constraint X < Y.

Only X = 1 has a supporting Y value. Revising (X, Y) therefore leaves X = {1}. That revision prunes the left-hand variable; revising the reverse arc is a separate operation.

AC-3 repeatedly performs these revisions. If a domain shrinks, neighboring values may lose their support, so relevant arcs return to the queue.

  • An empty domain proves failure for the current CSP.
  • Nonempty domains don’t prove success. Three pairwise-adjacent regions can each retain both available colors, even though coloring a triangle with only two colors is impossible.

The broader lesson introduces node consistency for unary constraints and stronger consistency notions involving more variables. AC-3 establishes arc consistency.

Backtracking tries assignments and undoes choices when necessary.

Choose a variable, try a value, and continue if it fits the assignments already made. If it fails, try that variable’s next value. Return to an earlier variable only after exhausting the current one’s options.

The course also covers ways to improve that search:

  • Minimum remaining values—MRV: choose the variable with the fewest legal choices.
  • Degree heuristic: prioritize a variable constraining many other unassigned variables.
  • Least-constraining value—LCV: choose a value leaving other variables the most flexibility.
  • Inference during search: propagate consequences after making an assignment; restore removed possibilities when undoing it.
  • Min-conflicts local search: start with a complete assignment and change values to reduce violated constraints.

What understanding looks like: you can prune domains with AC-3 and follow backtracking in the specified variable and value order. Those two algorithms are the instructor’s explicit exam focus. Module 5 scope
